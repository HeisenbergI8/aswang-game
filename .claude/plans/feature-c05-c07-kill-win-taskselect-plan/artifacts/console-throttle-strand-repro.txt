======================================================================
METHOD
======================================================================
Config.Round.RespawnCooldown = 3s. RoundService.watchForDeath's non-round-death branch (LOBBY/STARTING
deaths) reads:

    local now = os.clock()
    local previous = lastRespawnAt[player.UserId]
    if previous ~= nil and now - previous < Config.Round.RespawnCooldown then
        return                              -- <-- returns BEFORE the three lines below
    end
    lastRespawnAt[player.UserId] = now
    player.Character = nil
    character:Destroy()
    applyBodyRule(player)

To land a second death inside the 3s window, natural LoadCharacterAsync latency in this Studio session
was highly variable (observed 0.48s–8s+ across ~8 trials), so the run below waited for the player's OWN
natural respawn (no manual override — this avoids a confound found in earlier attempts where a second,
independently-loaded character raced a still-pending LoadCharacterAsync coroutine from the first death
and later got silently clobbered by it, producing a false "recovery"). The moment the natural respawn's
new Character instance appeared, its Humanoid was killed again immediately.

======================================================================
INTERPRETATION
======================================================================
- The client snapshot repeatedly reports "you: ALIVE" (rounds #4, #5, #6 shown above; the pattern
  continues) with "alive 1" -- i.e. RoundService's PlayerState for this UserId is Alive and they are
  dealt into every subsequent round's roster -- while their actual player.Character is the SAME dead,
  Health=0 corpse (0_9193757) the whole time. The player is being counted as a living, killable,
  Aswang-eligible participant while physically unable to act (dead ragdoll, no control).
- No code path other than applyBodyRule's `Character == nil` branch ever clears or reloads this corpse,
  and the throttled branch is the only place that leaves Character non-nil after a death, so nothing
  will ever reach that branch again for this corpse on its own. This matches the static read of
  RoundService.luau:246-259 exactly.
